3. 技术栈选型调研

针对“响应式、高交互、低维护成本”的需求，我们对比了主流的前端框架与后端方案。 考虑到团队拥有AI编码工具辅助，我们可以选择生态最成熟、文档最丰富的技术栈，以最大化AI辅助的效率。

前端框架对比 (Frontend)

推荐方案: React + Next.js (或 Vite)
理由：组件生态最丰富，AI辅助编码准确率最高。Next.js 提供良好的图片优化 (Image Component) 和 SSR 能力，利于SEO（如果未来公开）。

数据库方案对比 (Database)

推荐方案: PostgreSQL (with JSONB)
理由：100万行数据对于Postgres是轻量级。使用JSONB存储不定长的Tags，既能享受关系型数据库的稳定，又能灵活查询标签。

4. 性能优化策略

在前端展示大量图片时，直接渲染会导致浏览器崩溃。 我们采用 "分页加载 (Pagination)" 结合 "懒加载 (Lazy Loading)" 的混合策略。 以下是性能优化的核心方案。

01. 缩略图策略

原图512x512 PNG较大。上传时应自动生成 256x256 的 WebP 格式缩略图用于列表展示，点击详情才加载原图。

02. 虚拟滚动 (Virtual Scroll)

如果在单页展示超过200张图片，必须使用虚拟滚动技术，仅渲染视口内的DOM元素，销毁视口外的元素。

03. 浏览器缓存

配置强缓存策略（Cache-Control: max-age=31536000），因为素材图片上传后极少修改。
